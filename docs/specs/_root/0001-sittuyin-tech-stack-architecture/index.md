# 0001. Adopt monorepo stack for Sittuyin web game

**Date**: 2026-11-22
**Status**: Accepted

## Summary

You are adopting a TypeScript monorepo (one shared repository with separate web, game server, database, and rules packages) to build a crisp 2D Burmese chess (Sittuyin) web game. The web app runs on TanStack Start and Cloudflare Workers with a custom React and SVG game board, while realtime multiplayer rooms run on Colyseus 0.18 on Fly.io in Singapore, backed by Neon PostgreSQL, Drizzle ORM, and Better Auth. Putting the Sittuyin rules in one shared zero dependency package lets both the browser and the authoritative game server run the exact same rules with zero drift, while keeping the operational footprint small enough for a tiny team.

## Decision

**Chosen option**: Option 1: TypeScript Monorepo with TanStack Start (Cloudflare Workers), Custom React SVG Board, Colyseus 0.18 (Fly.io Singapore), Neon PostgreSQL with Drizzle ORM, and Better Auth.

Build the Sittuyin web game as a `pnpm` and Turborepo TypeScript monorepo pairing TanStack Start on Cloudflare Workers with a custom React and SVG 2D board, a stateful Colyseus 0.18 game server on Fly.io Singapore, Neon PostgreSQL via Drizzle ORM, and Better Auth with its Anonymous plugin for instant guest play and Google OAuth account upgrades.

### Monorepo workspace layout

- `apps/web`: TanStack Start `1.0` application deployed to Cloudflare Workers via `@cloudflare/vite-plugin` in `vite.config.ts` (landing page, lobby, profiles, replays, Better Auth routes, match join ticket server function, custom 2D Sittuyin board UI). Never imports `apps/server`; shares types only through `packages/shared`.
- `apps/server`: Colyseus `0.18.x` Node.js 22 server deployed to Fly.io Singapore (`defineServer`, `SittuyinRoom`, matchmaking, private rooms, authoritative clocks, `GET /health`, HTTP Basic Auth `/monitor`, Playground disabled in production, completed match persistence).
- `packages/sittuyin-engine`: pure zero dependency TypeScript rules engine (board representation, drop phase validation, legal move generation, in place promotion, illegal stalemate detection, draw detection, Sittuyin FEN and UCI notation).
- `packages/db`: centralized owner of `drizzle.config.ts`, SQL migrations, Better Auth generated `auth-schema.ts` (output target of `npx auth@latest generate`), domain tables (`player_profiles`, `matches`), and runtime database factories (`createEdgeDb`, `createEdgeTxPool`, `createServerDb`).
- `packages/shared`: Zod schemas, shared Colyseus room state interfaces and message payload types (avoiding cross app `apps/web` to `apps/server` build edges in `turbo.json`), match join ticket claim types, and shared time control constants.
- `turbo.json`: separates client build time `VITE_*` variables from runtime secrets (`DATABASE_URL`, `BETTER_AUTH_SECRET`, `MATCH_TICKET_SECRET`) so cache keys stay clean and web and server build in parallel.

### Key architectural contracts

- **Authoritative server boundary**: the browser runs `packages/sittuyin-engine` purely for instant legal move highlights and optimistic previews; `apps/server` validates every drop, move, promotion, resignation, and clock flag using the exact same package before mutating Colyseus state.
- **Colyseus 0.18 idioms and CORS**: use `defineServer()` and `defineRoom()`, `@colyseus/sdk` with `Callbacks.get(room)`, `schema({ ... })` builder syntax keeping each schema under the 63 field limit (nested schemas for players and clocks), `onLeave(client, code: CloseCode)` with `CloseCode.CONSENTED`, and `@view()` with `StateView` if simultaneous hidden setup drops are enabled in the gameplay spec. Treat `VITE_GAME_SERVER_URL` as an `https://` origin (because `@colyseus/sdk` sends HTTP `POST /matchmake/...` before upgrading to WebSocket), configure Express CORS (`ALLOWED_ORIGINS`, allowing `Authorization`), and validate the WebSocket `Origin` header on upgrade (basis: installed `colyseus` skill).
- **Workers runtime secrets and SSR locale isolation**: enable `nodejs_compat` in `wrangler.jsonc`. Read all web runtime secrets via `cloudflare:workers` `env` inside lazy factories (`createEdgeDb(env.DATABASE_URL)` and `createAuth(env)`), never eagerly at module top level so Vite builds and Better Auth CLI generation succeed. Route localized pages under `/my/...` and `/en/...` (defaulting to `my` with cookie override synced to `player_profiles.locale` when signed in), keep `/api/auth/*` unprefixed so Google OAuth callbacks stay fixed, and wrap TanStack Start SSR in `src/server.ts` with Paraglide `AsyncLocalStorage` middleware so concurrent Myanmar and English requests never bleed across Worker isolates (basis: installed `tanstack-start-best-practices` and `cloudflare` skills).
- **Lazy guest sessions, profile creation, and atomic Google upgrade**: create anonymous Better Auth sessions lazily on first play intent (clicking Play, creating or joining a room, or minting a join ticket), never during landing page SSR, so crawlers and passive readers neither bloat `user`/`session` tables nor keep Neon compute awake. Enable Better Auth `cookieCache` (`compact`, 5 minute `maxAge`) to avoid a Neon HTTP query on every SSR request. Create `player_profiles` (with a generated unique `guest_<random8>` handle) inside Better Auth `databaseHooks.user.create.after`. Because `drizzle-orm/neon-http` does not support SQL transactions, run `onLinkAccount` inside a short lived `@neondatabase/serverless` WebSocket `Pool` transaction that reassigns `matches.red_user_id` and `matches.black_user_id` and merges profile stats before Better Auth deletes the anonymous user. Define `matches.red_user_id` and `matches.black_user_id` as nullable with `ON DELETE SET NULL` so linking an account mid match in another tab never throws a foreign key violation when Colyseus persists the finished game (basis: installed `better-auth-best-practices` and `neon-drizzle` skills).
- **Signed JWT match ticket and anti replay**: `apps/web` mints a 60 second HS256 JWT using `jose` (WebCrypto compatible in Workers and Node 22) carrying `sub`, `displayName`, `isAnonymous`, `rating`, `roomMode`, `timeControl`, `iss`, `aud`, `iat`, `exp`, and UUIDv4 `jti`, signed with `MATCH_TICKET_SECRET`. The client sets `client.auth.token` before calling `joinOrCreate` or `joinById`; `apps/server` verifies the token in `onAuth` via `context.token`, checks `jti` against a 60 second in memory single use set, enforces at most one active match per `sub` (blocking two tab self match rating farming), and derives room options from verified JWT claims rather than untrusted client input (basis: stateless JWT handoff between edge web and stateful game server).
- **Neon Node pool safety and Fly.io lifecycle**: `apps/server` connects to Neon via `pg` (`drizzle-orm/node-postgres`) with `max: 10`, `idleTimeoutMillis: 30000`, `connectionTimeoutMillis: 10000` (covering Neon scale to zero wakeups), a mandatory `pool.on("error", ...)` listener so idle PgBouncer drops never crash the Node process and kill live matches, and `pool.end()` on `SIGTERM`. Configure `fly.toml` with `auto_stop_machines = "off"` and `min_machines_running = 1` so Fly Proxy never suspends the machine during reconnection windows, expose `GET /health`, disable Colyseus Playground in production, and guard `/monitor` with HTTP Basic Auth (`MONITOR_AUTH_SECRET`). Because Fly `kill_timeout` (max 300 seconds) cannot drain 10 to 40 minute chess games, production deploys briefly lock new matchmaking, broadcast a shutdown warning, and end interrupted live rooms cleanly via `CloseCode.SERVER_SHUTDOWN` with no rating penalty (basis: installed `neon-postgres` skill; monolith first before horizontal scaling).
- **Core data model sketch (for downstream specs)**: `user`, `session`, `account`, `verification` (generated by Better Auth into `packages/db/src/auth-schema.ts`, using text UUID/ULID IDs matching `database.generateId`, with `isAnonymous` flag); `player_profiles` (`user_id` text PK/FK `ON DELETE CASCADE`, `handle` unique, `rating`, `rating_deviation`, `volatility`, `games_played`, `locale`); `matches` (`id`, `mode`, `time_control`, `red_user_id` nullable FK `ON DELETE SET NULL`, `black_user_id` nullable FK `ON DELETE SET NULL`, `winner_side`, `termination_reason`, `initial_setup_fen`, `moves_uci_json`, `started_at`, `ended_at`).

### Configuration required

- `DATABASE_URL`: pooled Neon PostgreSQL connection string (used by `apps/web` over Neon HTTP/WS and `apps/server` over `pg` pooled TCP).
- `DATABASE_URL_UNPOOLED`: unpooled Neon PostgreSQL connection string for Drizzle migrations (matches `neon env pull`).
- `BETTER_AUTH_SECRET`: minimum 32 character encryption secret for Better Auth sessions.
- `BETTER_AUTH_URL`: canonical web origin for Better Auth callbacks (unprefixed `/api/auth/callback/google`).
- `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`: Google OAuth credentials for guest account upgrades.
- `MATCH_TICKET_SECRET`: minimum 32 byte shared HS256 secret between `apps/web` and `apps/server` for 60 second room join tickets.
- `VITE_GAME_SERVER_URL`: public `https://` origin of the Fly.io Singapore Colyseus server (used for `/matchmake` HTTP calls and WebSocket upgrade).
- `ALLOWED_ORIGINS`: comma separated allowlist of web origins accepted by `apps/server` CORS and WebSocket `Origin` checks.
- `PORT` and `NODE_ENV`: HTTP port and production environment flag on `apps/server`.
- `SENTRY_DSN`, `VITE_SENTRY_DSN`, and `SENTRY_AUTH_TOKEN`: error tracking endpoints for Workers/Node and browser plus build time source map upload token.
- `MONITOR_AUTH_SECRET`: HTTP Basic Auth password guarding Colyseus `/monitor` in production.

## Consequences

**Positive**:

- One shared TypeScript rules engine (`packages/sittuyin-engine`) guarantees zero mismatch between legal move hints in the browser and authoritative validation on the server.
- Custom React plus SVG board rendering avoids fighting Western chess assumptions in third party libraries and avoids the bundle weight and accessibility gaps of a WebGL canvas engine.
- Colyseus 0.18 on an always on Fly.io Singapore machine provides low latency to Myanmar players, accurate in memory clocks, and built in reconnection without managing Redis on day one.
- Lazy Better Auth Anonymous sessions plus `cookieCache` keep guest onboarding instant while preventing bot traffic from waking Neon or filling user tables, and transactional `onLinkAccount` migration safely preserves match history on Google upgrade.
- Running `@sentry/cloudflare` plus lightweight `@sentry/react` (replay off) keeps `apps/web` well inside the Cloudflare Workers 3 MB free tier limit.

**Negative / tradeoffs**:

- Two deployment runtimes (Cloudflare Workers for `apps/web` and Fly.io for `apps/server`) require two deploy targets, separate secret sets, explicit CORS/Origin rules, and a signed HS256 `jose` ticket bridge instead of one shared server process.
- Holding live matches in memory on a single always on Fly.io machine means server deploys or unexpected host crashes abort active matches cleanly with no rating impact rather than draining 40 minute games live, and running `min_machines_running = 1` carries a small constant monthly Fly.io compute bill instead of scaling to zero.
- Building a custom React plus SVG board requires writing your own pointer drag physics, touch hit testing, and animation polish rather than inheriting Chessground defaults.
- Supporting bilingual `/my` and `/en` URL routing from day one adds copy maintenance on every new screen and requires careful `AsyncLocalStorage` SSR middleware and Burmese Unicode typography testing.

**Neutral**:

- Scaling beyond a single Fly.io machine (thousands of concurrent matches) later requires enabling `@colyseus/redis-presence`, `@colyseus/redis-driver`, and a shared Redis store for `jti` anti replay checks without changing the client protocol.
- No gameplay rules (exact drop phase turn order, traditional vs modern promotion edge cases, clock presets, or tournament draw rules) are locked in here; those belong in the next dedicated Sittuyin gameplay spec.
