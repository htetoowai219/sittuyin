# 0001. Implement realtime multiplayer room lifecycle, clocks, and lobby matchmaking

**Date**: 2026-11-23
**Status**: In Progress

## Summary

You are building the authoritative multiplayer game server (`apps/server`), shared wire contracts (`packages/shared`), and completed match storage (`packages/db`) for online Sittuyin (traditional Burmese chess). Players create public rooms that appear live in a shared lobby list (showing room title, host name, rating, time control, and picked side) or private rooms joined by a 6 character invite code, while up to 16 spectators can watch any match live. The Colyseus 0.18 room enforces hidden setup privacy through per client `StateView` filtering (a server mask that sends each player only their own draft pieces) backed by `toPlayerView`, runs a 60 second setup countdown with automatic setup completion (`autoCompleteSetup`) plus Fischer chess clocks (`rapid_10_5`, `rapid_15_10`, `classical_30_0`), handles reconnection grace periods and Fly.io deploy locks cleanly, and saves finished games to Neon PostgreSQL.

## Requirements

**User stories**:

- As a Sittuyin player, I want to create a public match in the live lobby (picking Red, Black, or Random and a custom room title) or share a 6 character private invite code with a friend so we can start playing or spectating in seconds.
- As a competitor in a timed game, I want hidden simultaneous officer setup with a 60 second auto complete safety net, accurate Fischer increment chess clocks, draw offers, resignation, pre move abort, in room rematches, and a 60 second mobile reconnection window so online games feel fair and resilient.
- As an engineer operating `apps/server`, `packages/shared`, and `packages/db`, I want signed 60 second HS256 JWT join tickets with single use `jti` replay protection, single active seated match enforcement, Colyseus 0.18 schemas well under the 63 field limit, graceful Fly.io maintenance locking, and asynchronous Neon PostgreSQL match persistence with retry backoff.

**Acceptance criteria**:

- **AC-1**: `packages/shared` defines and exports Zod validated schemas and TypeScript types for `RoomModeSchema` (`"public_lobby"` and `"private_room"`, accepting `"quick_match"` as a backwards compatible legacy alias normalized to `"public_lobby"`), `PreferredSideSchema` (`"red" | "black" | "random"`), `RoleIntentSchema` (`"player" | "spectator"`), `TimeControlSchema` (`"rapid_10_5" | "rapid_15_10" | "classical_30_0"`), `TIME_CONTROL_CONFIGS`, `MatchJoinTicketClaimsSchema`, `LobbyRoomMetadataSchema`, all 10 client to server message payloads, all 8 server to client event payloads, and `RoomActionErrorSchema`.
- **AC-2**: `apps/server` registers Colyseus built in `LobbyRoom` (`"lobby"`) and `SittuyinRoom` (`"sittuyin"`) with `.enableRealtimeListing()`. Creating a `"public_lobby"` room lists it in the live lobby across `"waiting"`, `"setup"`, and `"playing"` phases (publishing `roomTitle`, `hostDisplayName`, `hostRating`, `hostPreferredSide`, `hostAssignedSide`, `timeControl`, `phase`, `playerCount`, `spectatorCount`) so opponents can join open rooms and spectators can watch live matches. Creating a `"private_room"` marks the room private (`setPrivate(true)`), assigns `this.roomId` to a collision checked 6 character uppercase alphanumeric invite code from `23456789ABCDEFGHJKLMNPQRSTUVWXYZ` (retrying up to 5 times), and allows joining directly via `joinById(inviteCode)`.
- **AC-3**: Host side assignment honors `preferredSide` (`"red"`, `"black"`, or `"random"` resolved via server `crypto.randomInt(2)`), assigns the second player joiner to the opposite side, assigns any client with `roleIntent === "spectator"` or any 3rd through 18th joiner (`maxClients = 18`, 2 players plus up to 16 spectators) as `"spectator"`, and automatically closes idle `"waiting"` rooms that receive no second player within 10 minutes using custom close code `4012` (`WAITING_TIMEOUT`).
- **AC-4**: `SittuyinRoomState` uses Colyseus 0.18 `schema()` builder syntax across five nested schemas (`SittuyinRoomState` with 28 fields, `SittuyinPlayer` with 8 fields, `SittuyinClockState` with 7 fields, `SittuyinPrivateSetup` with 2 fields, and `SittuyinHandCounts` with 5 fields, keeping every schema well below the 63 field limit). `redPrivate` and `blackPrivate` are decorated with `.view()` and populated exclusively from `toPlayerView(engineState, viewer)`: Red's `StateView` adds only `redPrivate`, Black's `StateView` adds only `blackPrivate`, and all spectators share one `spectatorView` (`new StateView()`) with neither added, ensuring hidden simultaneous setup drafts and unmasked rival hands never cross the wire.
- **AC-5**: Every client to server message (`setup_action`, `random_setup`, `move`, `resign`, `offer_draw`, `respond_draw`, `abort`, `offer_rematch`, `respond_rematch`, `ping`) is validated via Colyseus `validate(ZodSchema, handler)`, enforces `maxMessagesPerSecond = 20`, ignores or rejects spectator mutations with `FORBIDDEN_SPECTATOR`, returns a typed `Result<void, RoomActionError>` for `room.request()` callers, and emits an `"action_error"` message to the sender when an action is rejected so `room.send()` callers also receive structured feedback.
- **AC-6**: Entering `phase === "setup"` starts an authoritative 60 second (`60000` ms) setup countdown on `this.clock`. Players may send `setup_action` (`place`, `move`, `remove`, `apply_preset`, `clear`, `lock`, `unlock`) or `random_setup` (seeded on the server via `crypto.randomBytes(4).readUInt32LE(0)`). When both players lock in, or when the 60 second setup timer expires and the server invokes `autoCompleteSetup(engineState, side, seed)` for each unlocked side, the room commits both drafts atomically onto `board`, populates `initialSetupFen`, transitions to `phase = "playing"` with Red to move, and broadcasts `"match_started"`.
- **AC-7**: Entering `phase === "playing"` initializes `SittuyinClockState` from `TIME_CONTROL_CONFIGS[timeControl]` (`rapid_10_5`: `600000` ms initial plus `5000` ms increment; `rapid_15_10`: `900000` ms initial plus `10000` ms increment; `classical_30_0`: `1800000` ms initial plus `0` ms increment) and starts Red's clock immediately. The server tracks elapsed wall clock time using monotonic `performance.now()`, checks for flag expiry (`remainingMs <= 0`) every `100` ms via `this.clock.setInterval`, adds `incrementMs` to the mover's remaining time after each valid `"playing"` move before switching `activeSide`, and patches synchronized `redRemainingMs`, `blackRemainingMs`, and `syncedAtMs` (`Date.now()`) on every turn change plus once every `1000` ms while ticking. When a side reaches `0` ms, the match terminates immediately as `{ status: "win", winner: opponentSide, reason: "timeout" }`.
- **AC-8**: Abort is permitted during `"waiting"`, `"setup"`, or `"playing"` strictly before ply 2 (before Black completes fullmove 1), ending the match as `{ status: "aborted", winner: "", reason: "aborted_pre_move" }` with zero database persistence and zero rating impact. Resignation is permitted during `"setup"` (once 2 players are seated) or `"playing"`, ending the match as `{ status: "win", winner: opponentSide, reason: "resignation" }`.
- **AC-9**: Draw offers are permitted during `"playing"` when `drawOfferedBy === ""` and the offering side has not already made a draw offer during their current turn cycle (`lastDrawOfferPlyBySide[side] !== currentPly`). A pending draw offer is accepted via `respond_draw({ accept: true })` to end the match as `{ status: "draw", winner: "", reason: "agreed_draw" }`, declined via `respond_draw({ accept: false })` (clearing `drawOfferedBy` and broadcasting `"draw_declined"`), or cleared automatically whenever either player commits a valid board move.
- **AC-10**: When a match reaches `phase === "finished"`, seated players may send `offer_rematch` and `respond_rematch({ accept })`. If the opponent accepts while both players remain connected, the room swaps Red and Black seats (`player.side`), generates a fresh UUIDv4 `matchId`, resets `@sittuyin/engine` state via `createGame()`, rebinds `redPrivate` and `blackPrivate` `StateView` targets to the swapped players, resets `SittuyinClockState` and `movesUci`, transitions back to `phase = "setup"`, starts a fresh 60 second setup timer, and broadcasts `"rematch_started"`. If either player declines or leaves the room, any pending rematch offer is cancelled.
- **AC-11**: Non consented disconnects trigger `onDrop(client, code)`, setting `player.connected = false` and calling `this.allowReconnection(client, seconds)` with a `60` second grace window during `"setup"` and `"playing"` (`15` seconds while `"waiting"`). Setup timers and active chess clocks keep running during a drop. Successful return within the window (automatic SDK retry or manual `client.reconnect(reconnectionToken)` after a mobile tab reload) triggers `onReconnect(client)` and restores `player.connected = true`. If reconnection times out or the client leaves with `CloseCode.CONSENTED` (`4000`), `onLeave(client, code)` runs: in `"waiting"` or before ply 2 when consented it aborts cleanly; during `"setup"` or `"playing"` it terminates the match as a win for the remaining side (`reason: "abandonment"` on timeout or `"resignation"` on consented leave after ply 2) and releases `ActivePlayerRoomMap`.
- **AC-12**: Instance `onAuth(client, options, context)` verifies the bearer or `context.token` JWT with `jose` `jwtVerify` (HS256, `MATCH_TICKET_SECRET`, `issuer: "sittuyin-web"`, `audience: "sittuyin-server"`, `maxTokenAge: "60s"`), validates claims with `MatchJoinTicketClaimsSchema`, rejects replayed `jti` values against `UsedJtiStore` (60 second TTL sweep) with `ServerError(401, "TICKET_REPLAYED")`, blocks a user `sub` from occupying a player seat if already seated in another room in `ActivePlayerRoomMap` (`ServerError(409, "ACTIVE_MATCH_EXISTS")`), prevents self play against the same `sub` in the same room (downgrading the second tab to `"spectator"` or rejecting if private player only), and validates the HTTP/WebSocket `Origin` header against `ALLOWED_ORIGINS`.
- **AC-13**: `apps/server` exposes `GET /health` (returning `{ ok: true, maintenanceLocked, activeRooms }`), Basic Auth `/monitor`, and Basic Auth `POST /admin/maintenance` (guarded by `MONITOR_AUTH_SECRET`). Enabling maintenance lock or receiving `SIGTERM` (`onBeforeShutdown`) rejects new room creations with `ServerError(503, "SERVER_MAINTENANCE")`, broadcasts `"server_maintenance"` to all active rooms, marks interrupted in progress matches as `{ status: "aborted", winner: "", reason: "aborted_maintenance" }` with zero database loss record and zero rating penalty, disconnects clients with `CloseCode.SERVER_SHUTDOWN` (`4001`), and closes the Neon `pg` pool cleanly.
- **AC-14**: `packages/db` defines the Drizzle PostgreSQL `matches` table and `createServerDb(databaseUrl)` factory (`drizzle-orm/node-postgres` `pg.Pool` with `max: 10`, `idleTimeoutMillis: 30000`, `connectionTimeoutMillis: 10000`, and an attached `pool.on("error")` handler). Whenever a match that reached `phase === "playing"` (`initialSetupFen` non empty) terminates with a competitive result (`checkmate`, `stalemate`, `unavoidable_stalemate`, `threefold_repetition`, `fifty_move_rule`, `bare_king_fifty_move`, `insufficient_material`, `resignation`, `timeout`, `abandonment`, or `agreed_draw`), `SittuyinRoom` broadcasts `"match_ended"` immediately and persists the completed match row asynchronously with up to 2 exponential backoff retries (`500` ms, `1500` ms), logging to Pino and Sentry without crashing the room if Neon is unreachable or `DATABASE_URL` is unset in local development.

## Decision

**Chosen option**: Option 1: Authoritative Colyseus 0.18 `SittuyinRoom` and `LobbyRoom` with `@view()` `StateView` setup isolation, monotonic Fischer clocks, single use `jose` JWT anti cheat registries, and asynchronous Drizzle `matches` persistence.

Build the multiplayer layer across `packages/shared`, `packages/db`, and `apps/server` using Colyseus 0.18 `defineServer()` with built in `LobbyRoom` realtime listings and 6 character private room invite codes, nested `@colyseus/schema` 5 structures gated by `@view()` and `toPlayerView`, `this.clock` timers for the 60 second `autoCompleteSetup` countdown and 100ms monotonic Fischer chess clocks, in memory `UsedJtiStore` and `ActivePlayerRoomMap` anti cheat guards, and non blocking Drizzle ORM match persistence to Neon PostgreSQL.

**Implementation skills**: `colyseus` (`colyseus/skill`, `.agents/skills/colyseus/`) · `neon-postgres` (`neondatabase/agent-skills`, `.agents/skills/neon-postgres/`) · `neon-drizzle` (`neondatabase/ai-rules`, `.agents/skills/neon-drizzle/`) · `vitest` (`antfu/skills`, `.agents/skills/vitest/`) · `turborepo` (`vercel/turborepo`, `.agents/skills/turborepo/`) · `sentry-sdk-setup` (`getsentry/sentry-for-ai`, `.agents/skills/sentry-sdk-setup/`)

### Room lifecycle, matchmaking, and clock specification

**1. Lobby mode vs private room invite codes**:

- **Room modes**: `RoomModeSchema` accepts `"public_lobby"` and `"private_room"` (plus `"quick_match"` normalized via `normalizeRoomMode` to `"public_lobby"` so existing callers and tests stay valid).
- **Public lobby rooms (`"public_lobby"`)**:
  - Created with `this.setPrivate(false)` (visible to `LobbyRoom` subscribers).
  - Whenever room state or player counts change (`onCreate`, `onJoin`, `onDrop`, `onReconnect`, `onLeave`, phase transitions, or rematch reset), the room calls `await this.setMatchmaking({ metadata: { ...this.metadata, ...nextMeta } })` (spreading `this.metadata` per Colyseus 0.18 wholesale replacement semantics) and `updateLobby(this)`.
  - `LobbyRoomMetadata` carries: `roomTitle` (`string`, 1 to 48 chars), `roomMode` (`"public_lobby"`), `timeControl` (`TimeControl`), `phase` (`RoomPhase`), `hostDisplayName` (`string`), `hostRating` (`number`), `hostPreferredSide` (`"red" | "black" | "random"`), `hostAssignedSide` (`"red" | "black"`), `playerCount` (`0 | 1 | 2`), and `spectatorCount` (`number`, `0..16`).
  - Public rooms remain unlocked (`maxClients = 18`) while in `"waiting"`, `"setup"`, and `"playing"` so other lobby users can see open challenges (`phase === "waiting" && playerCount === 1`) and join as the opponent, or click active games (`phase === "setup" || phase === "playing"`) to join as a live spectator.
- **Private rooms (`"private_room"`)**:
  - Created with `await this.setPrivate(true)` so they never appear in `LobbyRoom`.
  - In `onCreate`, `SittuyinRoom` generates a 6 character code from `23456789ABCDEFGHJKLMNPQRSTUVWXYZ` using `crypto.randomInt(32)`, checks `await matchMaker.getRoomById(code)` for collisions (retrying up to 5 times), assigns `this.roomId = code` and `this.state.inviteCode = code`.
  - Friends and spectators join directly by calling `client.joinById(inviteCode)`.

**2. Seat assignment and spectator StateView sharing**:

- **First player (host)**: when the first client with `roleIntent !== "spectator"` joins, `hostSessionId` is set to `client.sessionId`. If `hostPreferredSide === "red"` or `"black"`, the host receives that side; if `"random"`, the server draws `crypto.randomInt(2) === 0 ? "red" : "black"`.
- **Second player (challenger)**: when a second client with `roleIntent !== "spectator"` joins while one player seat (`"red"` or `"black"`) is still empty and `client.auth.sub !== hostUserId`, that client receives the remaining player seat.
- **Spectators**: any client joining with `roleIntent === "spectator"`, any 3rd through 18th client joining after both Red and Black seats are filled, or a second tab from the same `sub` as the host in a public room is assigned `side = "spectator"`.
- **`StateView` privacy wiring**:
  - `SittuyinRoom` holds one shared `spectatorView = new StateView()` instance for the room.
  - On `onJoin` (and on rematch side swap):
    - The Red player gets `client.view = new StateView()` with `client.view.add(this.state.redPrivate)`.
    - The Black player gets `client.view = new StateView()` with `client.view.add(this.state.blackPrivate)`.
    - Every spectator gets `client.view = this.spectatorView` (with neither `redPrivate` nor `blackPrivate` added, so Colyseus encodes the spectator patch once per tick for all 16 spectators).
  - Whenever `this.engineState` changes during `"setup"`, `"playing"`, or `"finished"`, `syncSchemaFromEngine()` calls:
    - `const specView = toPlayerView(this.engineState, "spectator")` to populate public `SittuyinRoomState` fields (`currentFen = toFen(this.engineState)`, `initialSetupFen`, `redPlacedCount = specView.placedCounts.red`, `blackPlacedCount = specView.placedCounts.black`, `redSetupReady = specView.setupReady.red`, `blackSetupReady = specView.setupReady.black`, `turn`, `halfmoveClock`, `bareKingClock`, `fullmoveNumber`).
    - `const redView = toPlayerView(this.engineState, "red")` to sync `this.state.redPrivate.myDraft` and `this.state.redPrivate.hand` (`redView.hands.red`).
    - `const blackView = toPlayerView(this.engineState, "black")` to sync `this.state.blackPrivate.myDraft` and `this.state.blackPrivate.hand` (`blackView.hands.black`).
  - When a client permanently leaves in `onLeave`, if they had a dedicated player `StateView` (`client.view && client.view !== this.spectatorView`), the room calls `client.view.dispose()` to release its view bitmask cleanly.

**3. Authoritative 60 second setup phase timer and `autoCompleteSetup`**:

- As soon as both `"red"` and `"black"` seats are filled, `this.state.phase` transitions from `"waiting"` to `"setup"`, the 10 minute waiting timeout is cleared, `this.engineState` is initialized with `createGame()`, `this.state.clock.setupRemainingMs` is set to `60_000`, `this.state.clock.syncedAtMs` is set to `Date.now()`, and `setupStartedAtPerfMs = performance.now()`.
- A 100ms room timer (`this.clock.setInterval`) tracks `elapsedSetupMs = performance.now() - setupStartedAtPerfMs`:
  - Every `1000` ms, `this.state.clock.setupRemainingMs` is patched to `Math.max(0, 60_000 - Math.floor(elapsedSetupMs))` and `syncedAtMs = Date.now()`.
  - If `elapsedSetupMs >= 60_000` while `this.state.phase === "setup"`:
    - For each side in `["red", "black"] as const`, if `!this.engineState.setupReady[side]`, the server generates a 32 bit CSPRNG seed via `crypto.randomBytes(4).readUInt32LE(0)` and calls `autoCompleteSetup(this.engineState, side, seed)`, updating `this.engineState = result.value`.
    - Because `autoCompleteSetup` preserves already placed officers, places any unplaced Rooks on rank 1 or rank 8 first, fills remaining behind pawn squares legally, and locks in automatically, locking the second side commits both drafts atomically onto `board`, sets `initialSetupFen`, and transitions `this.engineState.phase` to `"playing"`.
- Transitioning to `"playing"` (whether by manual second player `lock` or timer `autoCompleteSetup`) clears the setup timer, sets `this.state.clock.setupRemainingMs = 0`, records `matchStartedAt = new Date()`, starts Red's chess clock, and broadcasts `"match_started"` with `{ matchId, initialSetupFen, redRemainingMs, blackRemainingMs, syncedAtMs }`.

**4. Authoritative Fischer chess clocks (`rapid_10_5`, `rapid_15_10`, `classical_30_0`)**:

- At the start of `"playing"`, `redRemainingMs` and `blackRemainingMs` are initialized to `TIME_CONTROL_CONFIGS[timeControl].initialMs`, `incrementMs` to `TIME_CONTROL_CONFIGS[timeControl].incrementMs`, `activeSide = "red"`, `running = true`, `syncedAtMs = Date.now()`, and `lastClockTickPerfMs = performance.now()`.
- Every `100` ms on `this.clock.setInterval`:
  - Compute `nowPerf = performance.now()` and `deltaMs = nowPerf - lastClockTickPerfMs`; set `lastClockTickPerfMs = nowPerf`.
  - Subtract `deltaMs` from the room's internal floating point counter `internalRemainingMs[activeSide]`.
  - If `internalRemainingMs[activeSide] <= 0`:
    - Clamp `internalRemainingMs[activeSide] = 0`, patch `this.state.clock.redRemainingMs` and `this.state.clock.blackRemainingMs`, stop the clock (`running = false`, `activeSide = ""`), and finish the match with `{ status: "win", winner: opponentOf(activeSide), reason: "timeout" }`.
  - Otherwise, if `nowPerf - lastClockSyncPerfMs >= 1000`:
    - Patch `this.state.clock.redRemainingMs = Math.ceil(internalRemainingMs.red)`, `this.state.clock.blackRemainingMs = Math.ceil(internalRemainingMs.black)`, `this.state.clock.syncedAtMs = Date.now()`, and update `lastClockSyncPerfMs = nowPerf`.
- On every valid `"playing"` move by `side`:
  - First deduct elapsed time `nowPerf - lastClockTickPerfMs` from `internalRemainingMs[side]` and set `lastClockTickPerfMs = nowPerf`.
  - If `internalRemainingMs[side] <= 0`, flag immediately as `"timeout"` before applying the move.
  - Apply the move via `applyMove(this.engineState, move)`. If valid:
    - Push `lastRecord.uci` to `this.state.movesUci`.
    - Clear any active `drawOfferedBy = ""`.
    - If `nextEngineState.phase === "finished"`, stop the clock (`running = false`, `activeSide = ""`), patch final `remainingMs` and `syncedAtMs`, and finalize the match with `nextEngineState.outcome`.
    - If `nextEngineState.phase === "playing"`, add `incrementMs` to `internalRemainingMs[side]`, switch `activeSide = nextEngineState.turn`, and immediately patch `redRemainingMs`, `blackRemainingMs`, `activeSide`, and `syncedAtMs = Date.now()` so clients snap to the exact post increment clock on every turn change.

**5. Match lifecycle actions (abort, draw offer and response, resignation, rematch)**:

- **Abort (`abort` message)**:
  - Allowed only for seated players (`"red"` or `"black"`) when `phase === "waiting"`, `phase === "setup"`, or (`phase === "playing"` and `this.engineState.moveHistory.length < 2`, meaning before Black completes fullmove 1).
  - Stops all timers, sets `phase = "finished"`, `outcomeStatus = "aborted"`, `outcomeWinner = ""`, `outcomeReason = "aborted_pre_move"`, releases both players from `ActivePlayerRoomMap`, broadcasts `"match_ended"` (with `persisted: false`), and skips PostgreSQL persistence.
- **Resignation (`resign` message)**:
  - Allowed only for seated players during `phase === "setup"` (when both players have joined) or `phase === "playing"`.
  - Stops all timers, sets `phase = "finished"`, `outcomeStatus = "win"`, `outcomeWinner = opponentOf(senderSide)`, `outcomeReason = "resignation"`, releases `ActivePlayerRoomMap`, broadcasts `"match_ended"`, and persists the match if `phase` had reached `"playing"` (`initialSetupFen !== ""`).
- **Draw offer and response (`offer_draw`, `respond_draw`)**:
  - `offer_draw` is valid only for seated players during `phase === "playing"` when `this.state.drawOfferedBy === ""` and `this.lastDrawOfferPlyBySide[senderSide] !== this.engineState.moveHistory.length` (at most 1 draw offer per player per ply).
  - Sets `this.state.drawOfferedBy = senderSide`, records `this.lastDrawOfferPlyBySide[senderSide] = this.engineState.moveHistory.length`, and broadcasts `"draw_offered"` (`{ offeredBy: senderSide }`).
  - `respond_draw({ accept })` is valid only for the opponent of `this.state.drawOfferedBy` during `phase === "playing"`.
  - If `accept === true`: stops clocks, sets `phase = "finished"`, `outcomeStatus = "draw"`, `outcomeWinner = ""`, `outcomeReason = "agreed_draw"`, clears `drawOfferedBy = ""`, releases `ActivePlayerRoomMap`, broadcasts `"match_ended"`, and persists the match.
  - If `accept === false`: clears `drawOfferedBy = ""` and broadcasts `"draw_declined"` (`{ declinedBy: senderSide }`).
- **In room rematch (`offer_rematch`, `respond_rematch`)**:
  - Valid only for seated players when `phase === "finished"`, `outcomeReason !== "aborted_maintenance"`, and both seated players are still connected (`connected === true`).
  - `offer_rematch` sets `this.state.rematchOfferedBy = senderSide`, sets `senderPlayer.rematchAccepted = true`, and broadcasts `"rematch_offered"` (`{ offeredBy: senderSide }`).
  - `respond_rematch({ accept: false })` clears `this.state.rematchOfferedBy = ""` and resets `rematchAccepted = false` on both players.
  - `respond_rematch({ accept: true })` by the opponent (or `offer_rematch` sent by the opponent while an offer is already pending):
    - Verifies neither player is blocked by maintenance lock, re claims both players in `ActivePlayerRoomMap` for this `roomId` with swapped sides (`"red"` becomes `"black"` and `"black"` becomes `"red"`).
    - Swaps `player.side` on the two `SittuyinPlayer` entries, resets `rematchAccepted = false`, `rematchOfferedBy = ""`, `drawOfferedBy = ""`, `outcomeStatus = ""`, `outcomeWinner = ""`, `outcomeReason = ""`, and generates a new UUIDv4 `this.state.matchId`.
    - Disposes and recreates the two player `StateView` instances so the new Red player sees `this.state.redPrivate` and the new Black player sees `this.state.blackPrivate`.
    - Resets `this.engineState = createGame()`, clears `this.state.movesUci.clear()`, resets `SittuyinClockState` to initial time control values plus `setupRemainingMs = 60_000`, sets `this.state.phase = "setup"`, starts the 60 second setup timer, updates lobby metadata, and broadcasts `"rematch_started"` (`{ matchId: this.state.matchId, redSessionId, blackSessionId }`).

### State transitions

**Room phase state machine**:

```
[onCreate]
   |
   +==> phase = "waiting" (10m waiting timeout armed; listed in LobbyRoom if public_lobby)
          |
          +==> host leaves or 10m timeout (code 4012) ==> [onDispose]
          |
          +==> 2nd player joins ==> phase = "setup" (60s setup timer armed; @view() StateViews bound)
                 |
                 +==> abort (before ply 2) ==> phase = "finished" (aborted_pre_move, no DB row)
                 +==> resign / abandonment ==> phase = "finished" (win, no DB row if still in setup)
                 +==> both lock in OR 60s timer runs autoCompleteSetup
                        |
                        +==> phase = "playing" (initialSetupFen set; Red Fischer clock starts)
                               |
                               +==> abort (ply < 2) ==> phase = "finished" (aborted_pre_move, no DB row)
                               +==> move triggers engine terminal (checkmate / stalemate / draw rules)
                               |      ==> phase = "finished" (persist matches row asynchronously)
                               +==> clock reaches 0ms (100ms check)
                               |      ==> phase = "finished" (timeout, persist matches row)
                               +==> resign / respond_draw(accept: true) / abandonment
                               |      ==> phase = "finished" (persist matches row)
                               +==> server maintenance / SIGTERM
                                      ==> phase = "finished" (aborted_maintenance, code 4001, no DB row)

[phase = "finished"]
   |
   +==> offer_rematch + respond_rematch(accept: true)
   |      ==> swap Red and Black sides, new matchId, reset engine & clocks ==> phase = "setup"
   +==> all clients leave ==> [onDispose]
```

**Client connection and reconnection lifecycle**:

```
[client connects with client.auth.token]
   |
   +==> instance onAuth (verify HS256 jose JWT, check UsedJtiStore, check ActivePlayerRoomMap, check Origin)
          |
          +==> onJoin (assign side "red" | "black" | "spectator", bind StateView, claim ActivePlayerRoomMap)
                 |
                 +==> non consented disconnect ==> onDrop(client, code)
                 |      (player.connected = false; allowReconnection 60s in setup/playing, 15s in waiting;
                 |       setup timer and active chess clock keep ticking)
                 |      |
                 |      +==> client returns in time (auto retry or client.reconnect(token))
                 |      |      ==> onReconnect(client) (player.connected = true, full state snapshot reconciled)
                 |      |
                 |      +==> grace window expires (or clock flags first)
                 |             ==> onLeave(client, code) (forfeit as "abandonment" if active player, release seat)
                 |
                 +==> consented leave (room.leave(), code 4000)
                        ==> onLeave(client, 4000) (abort if waiting or ply < 2; else forfeit as "resignation")
```

### Key invariants

- **63 field schema ceiling**: every `@colyseus/schema` class stays strictly under 63 fields (`SittuyinRoomState`: 28, `SittuyinPlayer`: 8, `SittuyinClockState`: 7, `SittuyinPrivateSetup`: 2, `SittuyinHandCounts`: 5), verified by unit tests at definition time.
- **Hidden setup wire isolation**: during `phase === "setup"`, `SittuyinRoomState.currentFen` contains only the 16 starting pawns and the full uncommitted hand pool `[KFRRSSNNkfrrssnn]`; Red's draft squares exist only in `redPrivate` (added solely to Red's `StateView`), Black's draft squares exist only in `blackPrivate` (added solely to Black's `StateView`), and `spectatorView` subscribes to neither.
- **Single seated match per user**: at any moment, a `userId` (`sub`) appears at most once in `ActivePlayerRoomMap` as a seated `"red"` or `"black"` player across the entire server, and the two seated players in any room always have distinct `userId` values (`red.userId !== black.userId`).
- **Monotonic clock authority**: client messages never supply remaining time or clock timestamps; only `apps/server` deducts `performance.now()` deltas and awards `incrementMs`.
- **Clean persistence boundary**: matches that end before `phase === "playing"` (or abort before ply 2 or via `aborted_maintenance`) never insert a row into `packages/db` `matches`; every match that reaches `phase === "playing"` and finishes competitively inserts at most one row per `matchId` (idempotent primary key `id = matchId`).
- **Room timer hygiene**: all setup countdowns, 100ms clock intervals, and 10 minute waiting expiry timers use `this.clock.setTimeout` or `this.clock.setInterval` so Colyseus clears them automatically on `onDispose`.

### Security model

- **Trust boundary**: all WebSocket messages and room join options arriving at `apps/server` are untrusted; identity (`sub`, `displayName`, `isAnonymous`, `rating`) and match parameters (`roomMode`, `timeControl`, `preferredSide`, `roomTitle`, `roleIntent`) are trusted only after `jose` verifies the 60 second HS256 JWT signed with `MATCH_TICKET_SECRET`.
- **Single use ticket anti replay**: `UsedJtiStore` records every verified `jti` until its `exp * 1000` timestamp (plus a 5 second clock skew buffer) and rejects any duplicate `jti` before `onJoin` runs.
- **Role authorization inside rooms**: spectators (`side === "spectator"`) have read only access to public room state and `ping`; every state mutating message handler checks the sender's `SittuyinPlayer.side` against `"red"` and `"black"` and rejects spectator calls with `FORBIDDEN_SPECTATOR`.
- **Rate limiting and Origin validation**: `SittuyinRoom` sets `maxMessagesPerSecond = 20` so message floods disconnect the offending client automatically; HTTP CORS and WebSocket upgrade checks reject browser requests whose `Origin` header is not in `ALLOWED_ORIGINS`; `/monitor` and `POST /admin/maintenance` require timing safe HTTP Basic Auth with `MONITOR_AUTH_SECRET`.
- **Compliance and PII scope**: no payment data, health data, email addresses, or OAuth tokens pass through `apps/server` or `matches` (`matches` stores only opaque `user_id` text and public `display_name`).

### Configuration required

No new environment variables beyond those already established in stack spec `0001-sittuyin-tech-stack-architecture`:

- `MATCH_TICKET_SECRET`: minimum 32 byte shared HS256 secret used by `jose` in `apps/server` to verify 60 second room join tickets.
- `DATABASE_URL`: pooled Neon PostgreSQL connection string used by `packages/db` `createServerDb` (`apps/server` degrades gracefully with structured Pino warnings in local dev/tests when unset).
- `ALLOWED_ORIGINS`: comma separated allowlist of web origins accepted by `apps/server` Express CORS and WebSocket upgrade checks.
- `MONITOR_AUTH_SECRET`: HTTP Basic Auth password guarding `/monitor` and `POST /admin/maintenance`.
- `PORT` and `NODE_ENV`: HTTP listener port (default `2567`) and environment flag.
- `SENTRY_DSN`: optional Sentry error reporting endpoint for `apps/server` `onUncaughtException` and persistence failure alerts.

### Critical test scenarios

- **Shared Zod contracts and legacy `quick_match` normalization**: `MatchJoinTicketClaimsSchema`, `LobbyRoomMetadataSchema`, and all 10 client and 8 server message schemas validate well formed payloads, reject malformed squares or unknown actions, and normalize `"quick_match"` to `"public_lobby"`, verifies **AC-1**.
- **Public lobby listing and 6 character private invite codes**: creating a `"public_lobby"` room publishes metadata (`roomTitle`, `hostPreferredSide`, `hostAssignedSide`, `phase`, `playerCount`) to `LobbyRoom` and keeps it visible through `"setup"` and `"playing"`, while creating a `"private_room"` hides it from `LobbyRoom`, assigns a 6 character `roomId` / `inviteCode` (retrying on simulated collision), and allows joining via `joinById(inviteCode)`, verifies **AC-2**.
- **Side assignment, 16 spectator cap, and 10 minute waiting timeout**: host `preferredSide` (`"red"`, `"black"`, `"random"`) assigns Red and Black deterministically, routes joiners 3 through 18 (and `roleIntent: "spectator"`) to `"spectator"`, rejects a 19th client when `maxClients = 18` is full, and disconnects an unmatched `"waiting"` room after 10 minutes with close code `4012`, verifies **AC-3**.
- **Schema field count cap and `@view()` `StateView` privacy**: all 5 `@colyseus/schema` classes instantiate under the 63 field limit; during `"setup"`, Red's client state receives `redPrivate.myDraft` while `blackPrivate.myDraft` is empty, Black's client state receives `blackPrivate.myDraft` while `redPrivate.myDraft` is empty, and a connected spectator receives neither draft and sees only `redPlacedCount`, `blackPlacedCount`, `redSetupReady`, and `blackSetupReady`, verifies **AC-4**.
- **Message validation and spectator rejection**: sending an invalid Zod payload or a `setup_action` / `move` / `resign` from a spectator client leaves room state untouched, returns `{ ok: false, error: { code: "FORBIDDEN_SPECTATOR" } }` on `room.request()`, and sends `"action_error"` to the spectator, verifies **AC-5**.
- **Setup phase happy path and 60 second `autoCompleteSetup` fallback**: both players placing and locking 8 officers transitions immediately to `"playing"` and broadcasts `"match_started"`; when one or both players place only 3 officers and the 60 second setup timer expires, the server runs `autoCompleteSetup` preserving their 3 placed officers, places Rooks on the back rank, commits `initialSetupFen`, and starts `"playing"` with Red to move, verifies **AC-6**.
- **Fischer clock increment and 100ms flag detection**: in a `rapid_10_5` match, making a valid move adds `5000` ms increment to the mover's remaining clock and patches `syncedAtMs` immediately; advancing the clock past a player's remaining time terminates the match within 100ms as `{ status: "win", winner: opponent, reason: "timeout" }`, verifies **AC-7**.
- **Pre move 1 abort vs post ply 2 resignation**: calling `abort` during `"setup"` or on ply 1 ends the match as `"aborted_pre_move"` with `persisted: false`, whereas calling `abort` at ply 2 is rejected with `ABORT_WINDOW_CLOSED`; calling `resign` in `"setup"` or `"playing"` awards the win to the opponent, verifies **AC-8**.
- **Draw offer lifecycle and auto clear on move**: Red sends `offer_draw` (setting `drawOfferedBy = "red"`), a second `offer_draw` by Red on the same ply is rejected with `DRAW_COOLDOWN_ACTIVE`, making a board move auto clears `drawOfferedBy` to `""`, and accepting a pending draw offer ends the match as `"agreed_draw"`, verifies **AC-9**.
- **In room rematch with swapped sides and rebound `StateView`s**: after checkmate or resignation, Red offers a rematch and Black accepts; the room swaps their sides (`"red"` and `"black"`), generates a new `matchId`, rebinds `redPrivate` and `blackPrivate` `StateView` visibility to the swapped clients, resets the board and clocks to `"setup"`, and broadcasts `"rematch_started"`, verifies **AC-10**.
- **Reconnection grace period and abandonment timeout**: simulating an unexpected WebSocket drop (`onDrop`) during `"playing"` keeps `player.connected = false` while their clock continues running, allows seamless `client.reconnect(reconnectionToken)` within 60 seconds (`onReconnect`), and forfeits the match as `"abandonment"` if the 60 second window expires without reconnection, verifies **AC-11**.
- **HS256 `jose` JWT auth, `jti` anti replay, and single active match guard**: `onAuth` rejects expired or tampered tokens (`401`), rejects a second join attempt reusing the same `jti` (`401 TICKET_REPLAYED`), blocks a user `sub` already seated as Red in room A from taking a player seat in room B (`409 ACTIVE_MATCH_EXISTS`), and downgrades a second tab from the same `sub` joining room A to `"spectator"`, verifies **AC-12**.
- **Fly.io maintenance lock and graceful shutdown**: calling `POST /admin/maintenance` with Basic Auth (`{ locked: true }`) blocks new room creation with `503 SERVER_MAINTENANCE` and updates `GET /health`; invoking `onBeforeShutdown` broadcasts `"server_maintenance"`, ends active matches as `"aborted_maintenance"` with `persisted: false`, and disconnects clients with `CloseCode.SERVER_SHUTDOWN` (`4001`), verifies **AC-13**.
- **Asynchronous Drizzle `matches` persistence with retry backoff**: completing a match that reached `"playing"` inserts the exact `initial_setup_fen`, `moves_uci_json`, `winner_side`, `termination_reason`, and timestamps into `packages/db`, retries automatically when the first attempt throws a transient connection error, and logs without crashing when all retries fail, verifies **AC-14**.

## Build plan

Ordered using a **Tracer Bullet** approach (assumed project default since `AGENTS.md` and `docs/scope/` are not created yet): stand up the shared wire contracts and Drizzle `matches` schema first, then build an authenticated, `@view()` isolated playable room end to end, and thicken with lobby/invite codes, timers/clocks, match lifecycle actions, reconnection, maintenance lock, and persistence retries.

1. **Shared Zod wire contracts, ticket claims, and snapshot helpers (`packages/shared`)**: implement `constants.ts`, `tickets.ts` (`RoomModeSchema` with `"public_lobby"`, `"private_room"`, and legacy `"quick_match"` normalizer, `PreferredSideSchema`, `RoleIntentSchema`, `MatchJoinTicketClaimsSchema`, `LobbyRoomMetadataSchema`), `messages.ts` (all 10 client and 8 server Zod schemas plus `RoomActionErrorSchema`), and `snapshots.ts` (`roomSnapshotToPlayerGameView`), with Vitest unit tests, satisfies **AC-1**.
2. **Drizzle `matches` schema, Neon `pg` pool factory, and retry repository (`packages/db`)**: add `drizzle-orm`, `pg`, and `drizzle-kit` to `packages/db`, define `src/schema/matches.ts` (`matches` table and indexes), `src/client.ts` (`createServerDb` with `pool.on("error")` guard), and `src/repositories/matches.ts` (`insertCompletedMatch`), plus SQL migration generation and Vitest unit tests, satisfies **AC-14**.
3. **Colyseus 0.18 nested room schemas and `@view()` `StateView` privacy (`apps/server`)**: implement `SittuyinHandCounts`, `SittuyinPrivateSetup`, `SittuyinClockState`, `SittuyinPlayer`, and `SittuyinRoomState` in `apps/server/src/rooms/schema/SittuyinRoomState.ts` and wire `syncSchemaFromEngine` using `toPlayerView` plus per player `StateView` and shared `spectatorView`, with Vitest tests verifying the 63 field cap and zero draft leakage across Red, Black, and spectators, satisfies **AC-4**.
4. **HS256 `jose` JWT verification, `UsedJtiStore`, `ActivePlayerRoomMap`, and Origin guards (`apps/server`)**: add `jose` to `apps/server`, implement `src/auth/ticket-verifier.ts` and `src/auth/anti-cheat-registry.ts`, enforce instance `onAuth` token verification, single use `jti`, single active player match per `sub`, self play downgrade, and WebSocket `Origin` checks, with `@colyseus/testing` auth and anti cheat tests, satisfies **AC-12**.
5. **Public `LobbyRoom` listing, 6 character private invite codes, seat assignment, and spectators (`apps/server`)**: register `LobbyRoom` and `SittuyinRoom.enableRealtimeListing()` in `app.config.ts`, implement `src/rooms/invite-code.ts`, wire `hostPreferredSide` (`"red"`, `"black"`, `"random"`), 18 client capacity (2 players + 16 spectators), live lobby metadata updates, and the 10 minute `"waiting"` expiry timer (close code `4012`), with integration tests, satisfies **AC-2**, **AC-3**.

7. **Authoritative monotonic Fischer chess clocks (`apps/server`)**: implement the 100ms `performance.now()` clock loop on `this.clock.setInterval` for `rapid_10_5`, `rapid_15_10`, and `classical_30_0`, Fischer increment application on valid moves, immediate turn change plus 1000ms state patches, and flag timeout termination, with deterministic clock unit and room tests, satisfies **AC-7**.
8. **Match lifecycle actions (abort, draw offer and response, resignation, and in room rematch) (`apps/server`)**: implement `abort` (before ply 2), `resign`, `offer_draw` (1 per ply, auto cleared on move), `respond_draw`, `offer_rematch`, and `respond_rematch` (swapping Red and Black seats, rebinding `StateView`s, and resetting the board and clocks in place), with `@colyseus/testing` lifecycle tests, satisfies **AC-8**, **AC-9**, **AC-10**.

## Consequences

**Positive**:

- Combining `@sittuyin/engine` `toPlayerView` with Colyseus 0.18 `@view()` `StateView` filtering guarantees hidden simultaneous setup drafts and remaining officer hands never leave the server to opponents or spectators while encoding spectator state only once per tick via a shared `spectatorView`.
- Using Colyseus built in `LobbyRoom` for public rooms and setting `this.roomId` to the 6 character invite code for private rooms lets players browse live public rooms or join private games directly via `joinById(code)` without an extra lookup database table.
- Measuring chess clocks and the 60 second setup timer with monotonic `performance.now()` at 100ms precision while patching synchronized schema fields only on turn changes and 1 second intervals keeps clock flagging accurate without flooding 18 connected clients with 20Hz clock patches.
- Running Drizzle `matches` persistence asynchronously with 2 backoff retries ensures transient Neon scale to zero wakeups never stall the `"match_ended"` broadcast or crash active rooms.

**Negative / tradeoffs**:

- Keeping `UsedJtiStore` and `ActivePlayerRoomMap` in memory on a single always on Fly.io Singapore machine means horizontal scaling to multiple Fly.io machines later will require moving both maps and Colyseus presence to Redis (`@colyseus/redis-presence` and `@colyseus/redis-driver`).
- Enabling `@view()` on `redPrivate` and `blackPrivate` switches Colyseus from a single room wide patch buffer to per view encoding (3 distinct views per room: Red, Black, and the shared `spectatorView`), adding a small CPU overhead that is negligible for a 2 player plus 16 spectator board game.
- Leaving `matches.red_user_id` and `matches.black_user_id` as nullable text columns until the upcoming accounts and Better Auth spec lands means foreign key constraints to `user.id` will be added in the accounts migration.

**Neutral**:

- Glicko 2 rating calculation (`player_profiles` updates) is intentionally omitted from this room spec and will hook into completed match persistence in the dedicated accounts, Glicko 2 ratings, and match replay spec.
- Connecting `apps/web` `<SittuyinMatchWorkspace>` to `SittuyinRoom` via `ColyseusMatchAdapter` and building the lobby/invite UI will consume the `packages/shared` contracts settled here.
