# 0002. Build online lobby, private room invite flow, guest ticket minting, and ColyseusMatchAdapter in apps/web

**Date**: 2026-11-23
**Status**: Accepted

## Summary

You are connecting `apps/web` to the authoritative Colyseus 0.18 multiplayer game server (`apps/server`) so players can host and join live Burmese chess (Sittuyin) matches in the browser without creating an account first. TanStack Start server functions (server endpoints that run on Cloudflare Workers) issue a signed HTTP only guest cookie (`sittuyin.guest.v1`) and mint 60 second single use JSON Web Tokens (`MATCH_TICKET_SECRET`) that authenticate room creation and joins across domains. A new `/$locale/online` lobby route connects to Colyseus `LobbyRoom` to display open challenges and live matches for spectators alongside a Create Room modal, a 6 character private invite code join bar, and an editable guest display name badge. Inside `/$locale/room/$roomId`, `ColyseusMatchAdapter` plugs into `<SittuyinMatchWorkspace>` with optimistic local validation over `@sittuyin/engine`, hidden simultaneous setup over `roomSnapshotToPlayerGameView`, a 60 second setup countdown, interpolated Fischer chess clocks, draw and rematch negotiations, pre move abort, spectator view, and automatic 60 second tab reload reconnection.

## Requirements

**User stories**:

- As a Sittuyin player visiting the site for the first time, I want an instant guest identity (`Guest_XXXX`, editable display name, `1500` starting rating) and a live `/$locale/online` lobby where I can filter by time control, create a public challenge, or join an open room in one click without registering an account first.
- As a player inviting a friend to a private game, I want to create a private room that mints a 6 character invite code and a shareable `/$locale/room/$inviteCode` URL, shows a waiting card over the teak board with one click Copy Invite Link and Copy Code buttons, and transitions automatically into the 60 second hidden setup phase as soon as my friend joins.
- As a competitor or spectator in a live online match, I want instant board feedback validated by `@sittuyin/engine`, a 60 second setup countdown, smooth Fischer increment clocks, pre move abort, draw and rematch offers, spectator mode (`0/8` to `8/8` setup progress without draft leaks), and automatic reconnection if my mobile browser tab reloads during a game.

**Acceptance criteria**:

- **AC-1**: `apps/web` exposes three TanStack Start server functions (`getOrCreateGuestSessionFn`, `updateGuestDisplayNameFn`, and `mintMatchJoinTicketFn`) in `apps/web/src/server/match-ticket.ts` that store a 30 day sliding HTTP only `SameSite=Lax` HS256 signed guest cookie (`sittuyin.guest.v1`, carrying `sub` as `guest_<uuid>`, `displayName` of 1 to 32 trimmed characters defaulting to `Guest_<4hex>`, `rating: 1500`, `isAnonymous: true`, and `issuedAt`), allow updating `displayName` while preserving `sub` and `rating`, and mint a 60 second HS256 JWT (`issuer: "sittuyin-web"`, `audience: "sittuyin-server"`, UUIDv4 `jti`) validated by `MatchJoinTicketClaimsSchema` from `@sittuyin/shared` without ever trusting `sub`, `rating`, or `isAnonymous` from client request payloads.
- **AC-2**: `apps/web/src/routes/$locale/online.tsx` connects to Colyseus `LobbyRoom` (`"lobby"`), displays live connection status, time control filter pills (`"all"`, `"rapid_10_5"`, `"rapid_15_10"`, `"classical_30_0"`), an editable guest display name bar, a 6 character uppercase alphanumeric invite code input box, a Create Room modal (`roomMode`: `"public_lobby"` or `"private_room"`, `timeControl`, `preferredSide`: `"red"`, `"black"`, or `"random"`, and optional `roomTitle` up to 48 characters), an Open Challenges section (`phase === "waiting" && playerCount === 1` with a Join Challenge action), and a Live Matches section (`phase === "setup" || phase === "playing"` showing spectator count `0..16` with a Watch Live action).
- **AC-3**: Submitting the Create Room modal calls `mintMatchJoinTicketFn`, sets `client.auth.token`, creates a fresh authoritative room via `client.create("sittuyin")`, stores the returned `room.reconnectionToken` in `localStorage` (`sittuyin.reconnect.v1`, 65 second TTL keyed by `room.roomId`), and navigates to `/$locale/room/$roomId` (where `$roomId` is the 6 character `inviteCode` for private rooms or the Colyseus `roomId` for public rooms) while passing the active Colyseus `Room` instance through an in memory handoff registry so navigation does not drop the newly created socket.
- **AC-4**: Opening `/$locale/room/$roomId` directly (or via the lobby Join, Watch, or 6 character invite code input) first consumes any handed off active `Room` instance for `$roomId`; otherwise it checks `sittuyin.reconnect.v1` for a non expired `reconnectionToken` matching `$roomId` and the current `guest.sub` and attempts `client.reconnect(reconnectionToken)` before falling back to `mintMatchJoinTicketFn` (with `roleIntent: "spectator"` when `?role=spectator` is present, else `"player"`) and `client.joinById(roomId.toUpperCase())`.
- **AC-5**: While `roomPhase === "waiting"`, `<SittuyinMatchWorkspace>` renders the teak board in a non interactive waiting state with a centered waiting overlay card showing the room title, time control badge, host preferred side, the 6 character invite code (when `inviteCode` is present), one click Copy Invite Link and Copy Code buttons with localized toast confirmation, and an Abort Room button that leaves cleanly and returns to `/$locale/online`.
- **AC-6**: `ColyseusMatchAdapter` converts incoming `SittuyinRoomState` updates (`room.onStateChange` and `Callbacks.get(room)`) into a plain `SittuyinRoomSnapshot` and calls `roomSnapshotToPlayerGameView(snapshot, viewer)` from `@sittuyin/shared` (where `viewer` is derived from `snapshot.players[room.sessionId]?.side ?? "spectator"`), keeping opponent setup draft coordinates completely absent from spectator and rival views while updating `view.placedCounts` (`0/8` to `8/8`) and `view.setupReady` live.
- **AC-7**: When a seated player dispatches `dispatchSetup(action)` or `dispatchMove(move)`, `ColyseusMatchAdapter` validates the action locally first with `@sittuyin/engine` (`applySetupAction` or `applyMove`), immediately returning `{ ok: false, error }` for illegal actions (triggering the workspace's localized toast and square shake with zero network round trip), applies an optimistic local `PlayerGameView` preview for legal actions while sending `"setup_action"` or `"move"` to the room, and reconciles to authoritative room snapshots or rolls back and toasts if `"action_error"` arrives.
- **AC-8**: During `roomPhase === "setup"`, `<SetupTray>` and `<SittuyinMatchWorkspace>` display the authoritative 60 second setup countdown (`online.setupRemainingMs` interpolated locally at 100ms intervals from `setupSyncedAtMs` with a warning style below 15 seconds), route Random Setup clicks to the server `"random_setup"` message, and transition cleanly into `roomPhase === "playing"` when both players lock in or when the server runs `autoCompleteSetup` at `0` seconds and broadcasts `"match_started"`.
- **AC-9**: During `roomPhase === "playing"`, `ColyseusMatchAdapter` supplies `MatchClockState` interpolated locally at 100ms intervals from `clock.redRemainingMs`, `clock.blackRemainingMs`, `clock.activeSide`, and `clock.syncedAtMs`, snapping accurately to server post increment timestamps on every turn change and triggering the existing `AudioEngine` low time warning (`30` seconds) and critical wooden ticks (`10` seconds).
- **AC-10**: `<SittuyinMatchWorkspace>` renders online lifecycle controls driven by `adapter.online`: an Abort Match button when `online.canAbort` is true (`waiting`, `setup`, or `playing` before ply 2), Resign and Offer Draw buttons during active play, an incoming Draw Offer banner (`Accept Draw` or `Decline`) when `online.drawOfferedBy` equals the opponent side, localized outcome banners for all `TerminationReason` values (`abandonment`, `agreed_draw`, `aborted_pre_move`, `aborted_maintenance`, `timeout`, `resignation`, and engine outcomes), and an in room Rematch offer and response bar (`Offer Rematch`, `Accept Rematch`, `Decline`) during `roomPhase === "finished"` that swaps Red and Black seats and resets to `roomPhase === "setup"` on `"rematch_started"`.
- **AC-11**: Clients assigned `viewer === "spectator"` render `<SittuyinMatchWorkspace>` in read only mode (`isInteractive === false`) with a live spectator count badge, live `0/8` to `8/8` setup progress counters, live countdown clocks, local board orientation flip, move history scrubbing with the pulsing "Back to live" unseen ply pill, and Copy FEN or UCI export, with all setup, move, draw, resign, abort, and rematch mutation controls hidden.
- **AC-12**: `ColyseusMatchAdapter` and `/$locale/room/$roomId` handle network drops and server error codes gracefully: showing a reconnecting banner with opponent disconnection status (`players[side].connected === false`) during the 60 second grace period, displaying an active match conflict alert with a direct link to the existing room on `409 ACTIVE_MATCH_EXISTS`, and showing localized recovery alerts with a one click Return to Online Lobby action on `4012` (`WAITING_TIMEOUT`), `4013` (`ROOM_ABORTED`), `4001` or `503` (`SERVER_MAINTENANCE` / `"server_maintenance"` broadcast), and `404` invalid room or invite code.
- **AC-13**: The landing page (`/$locale/index.tsx`) and top workspace navigation include direct bilingual (`/my` and `/en`) links to `/$locale/online`, and all new lobby, invite, waiting card, setup timer, draw, abort, rematch, spectator, and connection recovery strings are localized in `apps/web/messages/my.json` and `apps/web/messages/en.json` with `line-height: 1.65` for Burmese script.

## Decision

**Chosen option**: Option 1: Stateless HS256 signed guest identity cookie with TanStack Start join ticket server functions, dedicated `/$locale/online` and `/$locale/room/$roomId` routes, and an optimistic `ColyseusMatchAdapter` backed by `@sittuyin/shared` `roomSnapshotToPlayerGameView`.

Extend `apps/web` with `@colyseus/sdk` (`^0.18.0`) and `jose` (`^6.2.2`), three TanStack Start server functions that manage a signed HTTP only guest cookie (`sittuyin.guest.v1`) and mint 60 second single use `MatchJoinTicketClaims` tokens, a live `/$locale/online` lobby browser subscribed to Colyseus `LobbyRoom`, and a `/$locale/room/$roomId` match route driving `<SittuyinMatchWorkspace>` through `ColyseusMatchAdapter` with local `@sittuyin/engine` validation, optimistic previews, 100ms clock interpolation, and 60 second `localStorage` reconnection recovery.

### State transitions

**1. Online room connection and reconnection state machine (`/$locale/room/$roomId`)**:

```
[Mount /$locale/room/$roomId]
  ├─ Check in memory pending room handoff registry (from Create Room modal)
  │    └─ Found matching roomId -> [Connected: bind ColyseusMatchAdapter, save StoredRoomReconnection]
  └─ Not in handoff registry -> fetch getOrCreateGuestSessionFn()
       ├─ StoredRoomReconnection exists in localStorage (roomId + userId match, Date.now() < expiresAtMs)
       │    ├─ client.reconnect(reconnectionToken) succeeds
       │    │    └─ [Connected: refresh StoredRoomReconnection, bind ColyseusMatchAdapter]
       │    └─ client.reconnect fails (expired or room disposed)
       │         └─ Clear stale StoredRoomReconnection -> fall through to fresh joinById
       └─ Fresh join flow: call mintMatchJoinTicketFn({ roomMode, timeControl, roleIntent })
            ├─ client.joinById(normalizedRoomId) succeeds
            │    └─ [Connected: save StoredRoomReconnection (if seated player), bind ColyseusMatchAdapter]
            ├─ Fails with 409 ACTIVE_MATCH_EXISTS
            │    └─ [Conflict error state: show "You have an active match in progress" alert + Return to Lobby]
            ├─ Fails with 503 SERVER_MAINTENANCE
            │    └─ [Maintenance error state: show server maintenance banner + Return to Lobby]
            └─ Fails with 404 / room not found / invalid code
                 └─ [Not found error state: show invalid or expired room code alert + Return to Lobby]
```

**2. `ColyseusMatchAdapter` optimistic action and reconciliation state machine**:

```
[Authoritative snapshot S_n synced from roomState via roomSnapshotToPlayerGameView]
  ├─ Player dispatches setup action or board move
  │    ├─ Run local @sittuyin/engine validation (applySetupAction / applyMove on current view state)
  │    │    ├─ Invalid ({ ok: false, error }) -> return error immediately (toast + square shake, no socket send)
  │    │    └─ Valid ({ ok: true, value: nextLocalState })
  │    │         ├─ Set optimisticView = toPlayerView(nextLocalState, viewer)
  │    │         └─ Send Colyseus message ("setup_action" or "move") to room
  │    ├─ Authoritative schema patch S_{n+1} arrives from room
  │    │    └─ Clear optimisticView, render authoritative roomSnapshotToPlayerGameView(S_{n+1}, viewer)
  │    └─ Server emits "action_error" message
  │         └─ Clear optimisticView (roll back to S_n), surface localized error toast
```

**3. Live room phase lifecycle inside `<SittuyinMatchWorkspace>`**:

```
[roomPhase = "waiting"] (waiting overlay card with invite code, Copy Link, Copy Code, Abort Room)
  ├─ Host clicks Abort Room -> room.send("abort") / room.leave(true) -> navigate to /$locale/online
  ├─ Server closes with 4012 WAITING_TIMEOUT -> show timeout alert with Return to Lobby CTA
  └─ Second player joins -> [roomPhase = "setup"] (60s setupRemainingMs countdown starts)
       ├─ Seated players place/swap/preset/random/lock officers; spectators see 0/8..8/8 progress
       ├─ Both lock in OR 60s timer triggers server autoCompleteSetup -> "match_started"
       └─ [roomPhase = "playing"] (100ms interpolated Fischer clocks running)
            ├─ Pre ply 2: seated player may click Abort Match -> [roomPhase = "finished" (aborted_pre_move)]
            ├─ Active play: moves, Offer Draw -> opponent Accept/Decline Draw, Resign, or Clock Flag
            └─ Terminal event ("match_ended") -> [roomPhase = "finished"] (clear StoredRoomReconnection)
                 ├─ Seated player clicks Offer Rematch -> opponent clicks Accept Rematch
                 │    └─ "rematch_started" (Red and Black seats swapped, new matchId) -> [roomPhase = "setup"]
                 └─ Player clicks Back to Online Lobby -> room.leave(true) -> navigate to /$locale/online
```

### API, component, and module surface

**Module layout (`apps/web/src/`)**:

- `server/guest-cookie.ts`: HS256 JWT signing and verification for the `sittuyin.guest.v1` HTTP only cookie using `jose` (`SignJWT`, `jwtVerify`), reading `MATCH_TICKET_SECRET` lazily from Cloudflare Workers `env` or `process.env` (with a safe development fallback secret in non production environments).
- `server/match-ticket.ts`: TanStack Start `createServerFn` endpoints (`getOrCreateGuestSessionFn`, `updateGuestDisplayNameFn`, `mintMatchJoinTicketFn`) validating inputs with Zod and signing 60 second `MatchJoinTicketClaims` tokens.
- `lib/colyseus/client.ts`: browser Colyseus `Client` factory reading `VITE_GAME_SERVER_URL` (defaulting to `http://localhost:2567` in local dev), plus an in memory `pendingRoomHandoff` registry (`setPendingRoomHandoff`, `consumePendingRoomHandoff`) so a room created in `/$locale/online` transfers cleanly to `/$locale/room/$roomId` without reconnecting.
- `lib/colyseus/reconnect-store.ts`: SSR safe browser `localStorage` helper (`sittuyin.reconnect.v1`) for saving, reading, pruning expired (> 65 seconds), and clearing `StoredRoomReconnection` tokens by `roomId`.
- `lib/colyseus/lobby-client.ts`: React hook `useOnlineLobby(serverUrl)` connecting to `client.joinOrCreate("lobby")`, handling `"rooms"`, `"+"`, and `"-"` messages validated against `LobbyRoomMetadataSchema`, and splitting rooms into `openChallenges` and `liveMatches`.
- `lib/adapters/colyseus-match-adapter.ts`: `ColyseusMatchAdapter` class and `useColyseusMatchAdapter(room, locale)` React hook implementing `MatchAdapter` with `Callbacks.get(room)` listeners, `roomSnapshotToPlayerGameView`, optimistic local `@sittuyin/engine` previews, 100ms clock and setup timer interpolation, and online lifecycle actions (`offerRematch`, `respondDraw`, `respondRematch`, `abortMatch`, `leaveRoom`).
- `lib/adapters/types.ts`: updated `MatchAdapter` and `ExtendedOutcome` types adding the optional `online: OnlineRoomLifecycleState` slice and online lifecycle callbacks.
- `components/sittuyin/`:
  - `WaitingRoomOverlay.tsx`: centered teak card displayed over the board during `roomPhase === "waiting"` with room title, time control, preferred side, 6 character invite code badge, Copy Invite Link and Copy Code buttons, and Abort Room button.
  - `OnlineMatchControls.tsx`: online action bar and banners inside the right rail of `<SittuyinMatchWorkspace>` (60 second setup countdown pill, pre move Abort button, Offer Draw button and incoming Draw Offer accept/decline banner, Resign confirmation, Rematch offer/accept/decline bar, opponent reconnecting banner, and server maintenance alert).
  - `CreateRoomDialog.tsx`: `shadcn/ui` dialog on `/$locale/online` for picking Public Lobby vs Private Invite Room, time control (`rapid_10_5`, `rapid_15_10`, `classical_30_0`), preferred side (`red`, `black`, `random`), and custom room title.
- `routes/$locale/online.tsx`: bilingual online lobby page with guest display name editor, 6 character invite code join bar, time control filter pills, Open Challenges grid, Live Matches spectator grid, and Create Room dialog trigger.
- `routes/$locale/room.$roomId.tsx`: live online match route orchestrating room handoff, stored token reconnection, fresh ticket minting and `joinById`, connection error recovery cards (`409`, `404`, `4012`, `4013`, `503`), and `<SittuyinMatchWorkspace adapter={colyseusAdapter} />`.

### Key invariants

- **Cookie authority over guest claims**: `mintMatchJoinTicketFn` never reads `sub`, `rating`, or `isAnonymous` from the client request body; those three claims come exclusively from the server verified `sittuyin.guest.v1` HTTP only signed cookie so a user cannot spoof another player's `sub` or inflate their rating from browser DevTools.
- **Strict workspace boundary**: `apps/web` never imports from `apps/server`; all shared schemas, message contracts, ticket claim types, and `roomSnapshotToPlayerGameView` come strictly from `@sittuyin/shared` and `@sittuyin/engine`.
- **Single socket across Create Room navigation**: creating a room in `/$locale/online` hands the live Colyseus `Room` object to `/$locale/room/$roomId` via `pendingRoomHandoff` in memory rather than disconnecting and rejoining, preserving the host's `sessionId` and avoiding a wasted 15 second waiting grace drop.
- **Hidden setup isolation on the client**: `ColyseusMatchAdapter` builds `PlayerGameView` strictly via `roomSnapshotToPlayerGameView(snapshot, viewer)`. Spectators and opponents only ever receive `placedCounts` (`0..8`) and `setupReady` booleans during `phase === "setup"`.
- **Monotonic client clock interpolation**: local 100ms countdown interpolation tracks elapsed time from the moment each `SittuyinClockSnapshot` arrives using `performance.now()` rather than subtracting `Date.now() - snapshot.clock.syncedAtMs` directly, preventing freeze or instant zeroing when a user's laptop or phone clock is skewed from the server clock.
- **Reconnection token hygiene**: `StoredRoomReconnection` entries in `localStorage` (`sittuyin.reconnect.v1`) expire 65 seconds after their last update and are deleted immediately when the player clicks Leave / Abort (`room.leave(true)`) or when the room transitions to `phase === "finished"`.

### Security model

- **Trust boundary**: browser storage (`localStorage`) and client function arguments are untrusted. Guest identity (`sub`, `displayName`, `rating`, `isAnonymous`) is stored in an HTTP only `SameSite=Lax` cookie (`sittuyin.guest.v1`, `Secure` in production) signed with HS256 using `MATCH_TICKET_SECRET`.
- **Short lived single use match tickets**: every call to `mintMatchJoinTicketFn` generates a fresh UUIDv4 `jti` and a 60 second expiration (`exp = iat + 60`) signed with `MATCH_TICKET_SECRET`. Replaying a captured token is blocked by `UsedJtiStore` on `apps/server`.
- **Display name sanitization**: `updateGuestDisplayNameFn` trims whitespace, strips ASCII control characters, enforces 1 to 32 Unicode characters (supporting Burmese and Latin scripts), and renders all display names and room titles as escaped React text nodes to prevent XSS.
- **Self play and spectator enforcement**: if a player opens their own public waiting room in a second browser tab (sharing the same `sittuyin.guest.v1` cookie `sub`), `apps/server` assigns the second tab `side = "spectator"` and `ColyseusMatchAdapter` automatically locks `isInteractive = false`; if the player tries to join a different room as a player while already seated in an active match, `apps/server` returns `409 ACTIVE_MATCH_EXISTS` and `apps/web` displays a recovery alert.
- **Compliance and PII scope**: guest cookies store only a random `guest_<uuid>` identifier and a user chosen handle (`Guest_XXXX`) with zero email addresses, passwords, payment data, or regulated PII.

### Configuration required

No new environment variable names beyond those defined in root stack spec `0001-sittuyin-tech-stack-architecture`:

- `MATCH_TICKET_SECRET`: shared 32+ byte secret on Cloudflare Workers (`apps/web`) and Fly.io (`apps/server`) used to sign and verify both the `sittuyin.guest.v1` guest cookie and the 60 second `MatchJoinTicketClaims` JWT (falls back to a deterministic development secret when `NODE_ENV !== "production"` so `pnpm dev` and `pnpm test` run out of the box).
- `VITE_GAME_SERVER_URL`: public origin of `apps/server` (defaults to `http://localhost:2567` in local development, `https://...` in production).

## Consequences

**Positive**:

- Players can jump straight into public lobby challenges or private 6 character invite games as guests (`Guest_XXXX`) with zero sign up friction while `apps/server` still receives cryptographically verified HS256 join tickets.
- Reusing `roomSnapshotToPlayerGameView` from `@sittuyin/shared` and `<SittuyinMatchWorkspace>` from `web/0001` keeps the custom Burmese teak board, setup tray, promotion overlay, move history, and Web Audio cues 100% shared between offline and online play.
- Optimistic local `@sittuyin/engine` validation makes piece drops and moves feel instantaneous while authoritative server patches and `"action_error"` rollbacks guarantee zero rule drift.
- Persisting `StoredRoomReconnection` in `localStorage` with a 65 second TTL lets mobile players survive accidental tab refreshes or brief network switches during the server's 60 second reconnection grace window.

**Negative / tradeoffs**:

- Because guest identity lives in an HTTP only browser cookie (`sittuyin.guest.v1`) until Better Auth lands, clearing browser cookies or switching devices generates a new guest `sub` and resets the guest's `1500` placeholder rating.
- Maintaining optimistic state previews in `ColyseusMatchAdapter` alongside authoritative Colyseus schema callbacks requires careful rollback handling whenever a race condition (such as clock flag expiry or simultaneous lock) rejects an action on the server.

**Neutral**:

- When the Better Auth and Neon PostgreSQL accounts spec (`user`, `session`, `player_profiles`, and Google OAuth upgrade) is built next, `getOrCreateGuestSessionFn` and `mintMatchJoinTicketFn` will read the Better Auth session cookie when present and fall back to or migrate `sittuyin.guest.v1` without changing `ColyseusMatchAdapter` or the Colyseus wire protocol.
